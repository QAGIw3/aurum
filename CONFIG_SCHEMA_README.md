### Configuration Schema

Generate a JSON Schema for `AurumSettings` to support validation and IDE hints.

Steps:

```bash
python - <<'PY'
from aurum.core.settings import get_settings_manager
path = get_settings_manager().export_schema('docs/config.schema.json')
print(f'Wrote {path}')
PY
```

Use the schema with JSON tooling or CI to validate overlays under `config/`.

# Config Schema Notes

This document outlines configuration schema details and conventions.

## Observability Standards (Logging & Correlation IDs)

- Structured logging is standardized across the codebase using JSON lines.
- Required fields in logs include: `timestamp`, `level`, `event`, `service`, `request_id`, `correlation_id`, and where available `trace_id`, `span_id`, `tenant_id`, `user_id`, `session_id`.
- Use `aurum.telemetry.context.log_structured(level, event, **fields)` for app-level logs, or `aurum.observability.logging.get_logger(name)` for component loggers that auto-inject context.
- HTTP request logs are emitted by middleware with event `http_request_completed` and fields `method`, `endpoint`, `status_code`, `duration_ms`.
- Correlation headers: clients may pass `X-Request-Id` and `X-Correlation-Id` (fallbacks autogenerated). Responses always include `X-Request-Id`, `X-Correlation-Id`, and when tracing is active `traceparent` (`00-<trace_id>-<span_id>-01`).
- Business metrics are recorded via `aurum.observability.metrics.get_metrics_client()` using names `aurum_http_requests_total` and `aurum_http_request_duration_ms` for API traffic.
